# 05. 제약조건 설정 — 세계관(OWA/CWA) + 검증 규칙

> 온톨로지는 어떤 가정 위에서 동작하는가를 명시하고,
> 잘못된 데이터가 들어왔을 때 어떻게 감지·거부할지를 정의한다.

---

## 1. 세계관 선택: OWA vs CWA

### OWL 기본: OWA (Open World Assumption)

OWL은 기본적으로 **개방 세계 가정**을 따른다.
"데이터에 없으면 거짓"이 아니라 "데이터에 없으면 알 수 없음".

| 상황 | OWA 해석 | CWA 해석 |
|------|---------|---------|
| `fd_yr5_ern_r` 결측 | "5년 수익률을 모른다" | "5년 수익률이 없다" |
| `isHedged` 없음 | "헤지 여부를 모른다" | "헤지 안 됨" |
| 운용사 코드 없음 | "운용사 정보를 모른다" | "운용사가 없다" |

**공모펀드 데이터에서 OWA 선택 이유:**
- 수익률 결측(최대 47%)이 "수익률 0%"가 아니라 "데이터 미수집"이기 때문
- 결측을 "해당 없음"으로 해석하면 NL2SQL 쿼리 결과 오염

### CWA 적용 범위 (예외적으로 닫힌 세계 가정)

다음 속성은 명시적으로 CWA를 적용한다:

| 속성 | CWA 근거 | 처리 방법 |
|------|---------|----------|
| `:saleStatus` | "판매중" / "판매완료" 외 제3의 상태 없음 | `owl:oneOf` 제약 |
| `:hasRiskGrade` | 6등급 외 등급 없음 | `owl:oneOf` 제약 |
| `:investsIn` | 7개 지역 외 없음 | `owl:oneOf` 제약 |
| 펀드 유형 서브클래스 | 정의된 유형 외 없음 | `owl:disjointUnionOf` |

```turtle
# 판매 상태 제약 (CWA)
:saleStatus rdfs:range [
    a rdfs:Datatype ;
    owl:oneOf ("판매중" "판매완료")
] .
```

## 2. OWL 제약조건 (Restrictions)

### 2-1. 필수 속성 (Cardinality)

```turtle
# 모든 PublicFund는 반드시 하나의 fundId를 가져야 함
:PublicFund rdfs:subClassOf [
    a owl:Restriction ;
    owl:onProperty :fundId ;
    owl:cardinality 1
] .

# 모든 PublicFund는 반드시 하나의 fundName을 가져야 함
:PublicFund rdfs:subClassOf [
    a owl:Restriction ;
    owl:onProperty :fundName ;
    owl:cardinality 1
] .

# managedBy는 정확히 하나 (운용사 1개)
:PublicFund rdfs:subClassOf [
    a owl:Restriction ;
    owl:onProperty :managedBy ;
    owl:cardinality 1
] .
```

### 2-2. 선택적 속성 (MaxCardinality)

```turtle
# 수익률은 최대 1개 값 (있거나 없거나)
:PublicFund rdfs:subClassOf [
    a owl:Restriction ;
    owl:onProperty :returnYear1 ;
    owl:maxCardinality 1
] .

# 벤치마크는 최대 1개
:PublicFund rdfs:subClassOf [
    a owl:Restriction ;
    owl:onProperty :followsBenchmark ;
    owl:maxCardinality 1
] .
```

### 2-3. 클래스 간 분리 (Disjoint)

```turtle
# 펀드 유형은 상호 배타적
owl:AllDisjointClasses [
    owl:members (
        :EquityFund :BondFund :BondMixedFund :EquityMixedFund
        :FoFund :MMF :MixedAssetFund :SpecialAssetFund
        :DerivativeFund :RentalFund :LoanFund
    )
] .
```

> 하나의 펀드가 주식형이면서 동시에 채권형일 수 없음.
> 위반 시 OWL 추론기가 Inconsistency로 감지.

### 2-4. 위험등급 범위 제약

```turtle
:hasRiskGrade a owl:ObjectProperty ;
    rdfs:range :RiskGrade ;
    a owl:FunctionalProperty .  # 위험등급은 정확히 1개
```

## 3. SHACL 검증 규칙 (데이터 품질 게이트)

SHACL(Shapes Constraint Language)로 실제 인스턴스 데이터를 검증한다.
TTL 적재 전 파이프라인에서 자동 실행.

### 3-1. PublicFund Shape

```turtle
ex:PublicFundShape a sh:NodeShape ;
    sh:targetClass :PublicFund ;

    # fundId 필수, 문자열
    sh:property [
        sh:path :fundId ;
        sh:minCount 1 ;
        sh:maxCount 1 ;
        sh:datatype xsd:string ;
        sh:message "종목번호(itm_no)는 필수입니다."@ko
    ] ;

    # fundName 필수
    sh:property [
        sh:path :fundName ;
        sh:minCount 1 ;
        sh:datatype xsd:string ;
        sh:message "종목명(itm_nm)은 필수입니다."@ko
    ] ;

    # managedBy 필수
    sh:property [
        sh:path :managedBy ;
        sh:minCount 1 ;
        sh:class :AssetManagementCompany ;
        sh:message "운용회사(or_co_xtn_itt_cd)는 필수입니다."@ko
    ] ;

    # 수익률 범위 제약 (-100 ~ 10000%)
    sh:property [
        sh:path :returnYear1 ;
        sh:minInclusive -100 ;
        sh:maxInclusive 10000 ;
        sh:message "1년 수익률이 유효 범위를 벗어납니다."@ko
    ] ;

    # 순자산 음수 불가
    sh:property [
        sh:path :netAsset ;
        sh:minInclusive 0 ;
        sh:message "순자산은 0 이상이어야 합니다."@ko
    ] .
```

### 3-2. RiskGrade Shape

```turtle
ex:RiskGradeShape a sh:NodeShape ;
    sh:targetClass :RiskGrade ;

    sh:property [
        sh:path :gradeOrder ;
        sh:minCount 1 ;
        sh:datatype xsd:integer ;
        sh:minInclusive 1 ;
        sh:maxInclusive 6 ;
        sh:message "위험등급 순서는 1~6 사이여야 합니다."@ko
    ] .
```

## 4. 데이터 정규화 규칙 (전처리 파이프라인)

온톨로지 적재 전 파이프라인에서 처리해야 할 정규화 규칙.

| 이슈 | 원본 값 | 정규화 값 | 처리 위치 |
|------|---------|---------|----------|
| 위험등급 공백 없음 | "높은위험" | "높은 위험" | 전처리 Python |
| 위험등급 코드 | "06" | NULL (또는 추후 매핑) | 전처리 Python |
| 환헤지 이상값 | "00080008" | NULL | 전처리 Python |
| 펀드유형 코드 | or_attr_desc = "06" | :DerivativeFund (파생형 추정) | 전처리 Python |
| 순자산 0원 | `fd_nast_suma = 0.0` | 유효값으로 처리 (0원 펀드 실재) | 유지 |
| 수익률 극단값 | 이론상 -100% 이하 | NULL 처리 | SHACL 검증 후 |

```python
# 전처리 정규화 사전 (파이프라인)
RISK_GRADE_NORMALIZE = {
    "높은위험": "높은 위험",
    "보통위험": "보통 위험",
    "낮은위험": "낮은 위험",
    "06": None,           # 불명확 → NULL
}

FUND_TYPE_NORMALIZE = {
    "06": "파생형",        # or_attr_desc 미변환 코드
}

HEDGED_NORMALIZE = {
    "Y": True,
    "N": False,
    "00080008": None,     # 이상값 → NULL
}
```

## 5. 제약조건 위반 시 처리 방침

| 위반 유형 | 처리 | 이유 |
|----------|------|------|
| 필수 속성 누락 (itm_no 없음) | 해당 인스턴스 **적재 거부** | 식별 불가 |
| 운용회사 코드 없음 (66건) | 해당 인스턴스 **적재 거부** | 관계 구성 불가 |
| 수익률 NULL | **허용 (트리플 미생성)** | OWA 원칙 |
| 위험등급 이상값 ("06") | NULL로 **정규화 후 적재** | 부분 정보 보존 |
| 순자산 음수 | **적재 거부** + 로그 기록 | 논리적 불가 |
| 펀드유형 중복 분류 | **적재 거부** + 알림 | Disjoint 위반 |
