# 02. 클래스 정의 — 공모펀드 온톨로지의 핵심 개념

> 데이터에서 반복 등장하는 독립적인 개념(명사)을 추출해 클래스로 정의한다.
> 클래스는 "같은 종류의 것들의 집합"이며, 인스턴스의 설계도 역할을 한다.

---

## 1. 클래스 계층 구조

```
owl:Thing
└── :FinancialProduct          # 금융상품 (최상위)
    └── :PublicFund            # 공모펀드 (이 TTL의 주 클래스)
        ├── :EquityFund        # 주식형 (or_attr_desc = '주식형')
        ├── :BondFund          # 채권형 (or_attr_desc = '채권형')
        ├── :BondMixedFund     # 채권혼합형
        ├── :EquityMixedFund   # 주식혼합형
        ├── :FoFund            # 재간접 (Fund of Funds)
        ├── :MMF               # MMF
        ├── :MixedAssetFund    # 혼합자산형
        ├── :SpecialAssetFund  # 특별자산형
        ├── :DerivativeFund    # 파생형 (or_attr_desc = '06' 정규화 후)
        ├── :RentalFund        # 임대형
        └── :LoanFund          # 대출형

:AssetManagementCompany        # 운용회사 (67개)
:BenchmarkIndex                # 벤치마크 지수
:RiskGrade                     # 위험등급 (6단계)
:InvestmentRegion              # 투자지역
:FundClass                     # 펀드 클래스 (A, C, E 등 판매수수료 구조)
```

---

## 2. 클래스별 정의

### 2-1. :PublicFund (공모펀드)

```turtle
:PublicFund a owl:Class ;
    rdfs:subClassOf :FinancialProduct ;
    rdfs:label "공모펀드"@ko, "Public Fund"@en ;
    rdfs:comment "불특정 다수에게 판매되는 집합투자기구. itm_no를 고유 식별자로 사용."@ko .
```

| 속성 | 근거 | 비고 |
|------|------|------|
| 단위 | 펀드 클래스(종류) 단위 | 동일 펀드가 A/C/E 클래스별로 별도 행 |
| 식별자 | `itm_no` | PK |
| 명칭 | `itm_nm`, `itm_abrv_nm` | 두 표현 모두 rdfs:label로 |

### 2-5. :RiskGrade (위험등급)

6단계 위험등급을 열거형 클래스로 정의:

```turtle
:RiskGrade a owl:Class ;
    rdfs:label "위험등급"@ko, "Risk Grade"@en ;
    owl:oneOf (
        :RiskGrade_VeryLow
        :RiskGrade_Low
        :RiskGrade_Medium
        :RiskGrade_High
        :RiskGrade_SomewhatHigh
        :RiskGrade_VeryHigh
    ) .

:RiskGrade_VeryLow a :RiskGrade ;
    rdfs:label "매우 낮은 위험"@ko ;
    :gradeOrder 1 .

:RiskGrade_Low a :RiskGrade ;
    rdfs:label "낮은 위험"@ko ;
    :gradeOrder 2 .

:RiskGrade_Medium a :RiskGrade ;
    rdfs:label "보통 위험"@ko ;
    :gradeOrder 3 .

:RiskGrade_SomewhatHigh a :RiskGrade ;
    rdfs:label "다소 높은 위험"@ko ;
    :gradeOrder 4 .

:RiskGrade_High a :RiskGrade ;
    rdfs:label "높은 위험"@ko ;
    :gradeOrder 5 .

:RiskGrade_VeryHigh a :RiskGrade ;
    rdfs:label "매우 높은 위험"@ko ;
    :gradeOrder 6 .
```

> 주의: 원본 데이터에 "높은위험"(공백 없음), "보통위험"(공백 없음), "06" 등 오염값 존재.
> 전처리 단계에서 정규화 사전 적용 후 인스턴스 생성.

## 3. 클래스 결정의 근거

### 왜 FundClass(클래스 종류)를 별도 클래스로 두지 않는가?

`itm_no`가 이미 클래스(A, C, E 등) 단위로 분리되어 있음.
같은 펀드의 A·C 클래스는 수수료 구조만 다르고 운용 전략은 동일.
온톨로지에서는 `prfd_attr_cd` (예: V101, M111)를 속성으로 두는 것으로 충분.

### 왜 운용회사를 별도 클래스로 두는가?

- "삼성자산운용이 운용하는 펀드 목록" → :managedBy 관계 탐색 필요
- Graph DB에서 운용사-펀드 엣지를 명시적으로 구성하면 다단 쿼리 가능
- 67개의 운용사 인스턴스를 미리 정의해 Entity Resolution 역할 수행

### 왜 BenchmarkIndex를 별도 클래스로 두는가?

- "같은 벤치마크를 추종하는 다른 펀드는?" 유형의 관계 탐색에 필수
- RDB에서는 JOIN 없이 단순 문자열 비교로 처리 가능하지만,
  Graph DB에서 :follows 관계를 쓰면 다단 추론(A→지수←B → A와 B는 같은 지수 추종)이 가능
