# 01. 범위 결정 — 공모펀드 온톨로지가 답해야 할 질문

> 온톨로지를 만들기 전, "어떤 질문에 답할 수 있어야 하는가"를 먼저 확정한다.
> 범위 밖 질문은 다른 DB(RDB, Vector DB)가 담당하므로 명확히 선을 긋는다.

## 2. 온톨로지가 답해야 할 질문 목록 (역량 질문)

### 2-1. 단순 조회 (난이도 하)

- "판매 중인 주식형 펀드를 알려줘"
- "국내 투자 펀드 중 위험등급이 낮은 것은?"
- "MMF 펀드 목록을 보여줘"
- "삼성자산운용이 운용하는 채권형 펀드는?"
- "환헤지가 되는 해외 펀드를 추천해줘"

### 2-2. 수치 비교 (난이도 중)

- "1년 수익률이 10% 이상인 주식형 펀드는?"
- "순자산이 1조 원 이상인 펀드를 알려줘"
- "글로벌 투자 펀드 중 3년 수익률 상위 5개는?"
- "위험등급 '높은 위험'이면서 5년 수익률이 있는 펀드 목록은?"

### 2-3. 관계 탐색 (난이도 중~상, Graph DB가 주력)

- "A 운용사의 펀드 중 배당형이면서 채권혼합형인 것은?"
- "이 펀드와 같은 벤치마크를 추종하는 다른 펀드는?"
- "개인 투자자용 펀드와 법인 투자자용 펀드의 차이는?"
- "재간접 펀드의 투자 지역 분포는?"

### 2-4. 답변 불가 (감점 대상, 명확히 차단)

- "이 펀드의 실시간 기준가는?" → 실시간 데이터 없음
- "어떤 펀드가 미래에 수익률이 높을까?" → 투자 권유 금지
- "이 펀드의 운용보고서 내용은?" → 비정형 데이터 필요 (Vector DB 담당)
- "이 펀드의 편입 종목 비중은?" → 구성종목 데이터 없음 (외부 수집 필요)

## 3. 온톨로지 범위 결정

### 포함 범위 (In Scope)

| 영역 | 근거 컬럼 |
|------|----------|
| 펀드 식별 | `itm_no`, `itm_nm`, `itm_abrv_nm`, `fss_itm_no` |
| 펀드 유형 분류 | `or_attr_desc` (주식형/채권형/MMF 등) |
| 위험 등급 | `zrin_fd_ivst_risk_grd_nm`, `zrin_fd_ivst_risk_gcd` |
| 투자 지역 | `fd_ivst_rgn_desc`, `ovrs_fd_desc` |
| 운용회사 | `or_co_xtn_itt_cd` |
| 수익률 (다기간) | `fd_wk1_ern_r` ~ `fd_mm18_ern_r` |
| 순자산 | `fd_nast_suma` |
| 판매 상태 | `sale_yn`, `thco_sale_yn` |
| 환헤지 여부 | `exchdg_yn` |

### 제외 범위 (Out of Scope)

| 제외 항목 | 이유 |
|----------|------|
| 실시간 기준가·NAV 변동 | 데이터 없음 |
| 편입 종목·비중 | 데이터 없음 (외부 수집 후 RDB 적재) |
| 운용보고서 텍스트 | Vector DB 담당 |
| 투자 권유 판단 | 법적 제한 |
| `itm_eabrv_nm` (종목영문약어명) | 95,447건 결측 (전체의 99.8%) |
| `kofia_fd_ccd` 상세 분류 체계 | 20자리 코드 해석 기준 불명확 |

## 5. 온톨로지의 역할 분담

```
질문 유형            주 담당 DB         온톨로지 역할
──────────────────────────────────────────────────────
수치 필터·정렬       RDB              클래스·속성 타입 정의로 쿼리 보조
의미 유사 검색       Vector DB         개념 계층 제공 (예: 재간접 ⊂ 펀드)
관계 다단 탐색       Graph DB          클래스 간 관계 정의 (managedBy 등)
LLM 답변 생성       HyperCLOVA X      rdfs:label/comment로 용어 맥락 제공
```

온톨로지 자체가 질문에 직접 답하는 것이 아니라,
세 DB가 정확하게 동작할 수 있도록 **개념 구조와 관계의 틀을 제공**하는 것이 목표.
