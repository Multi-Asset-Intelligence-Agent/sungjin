# 07. 품질 관리 — 의도대로 추론되는지 확인

> 온톨로지가 완성된 후, 실제로 원하는 질문에 올바른 답이 나오는지
> 단계별로 검증한다. 검증은 SPARQL 쿼리, SHACL 검사, 수동 확인의 3층으로 구성.

---

## 1. 검증 체계 전체 구조

```
[1단계] 적재 전 — SHACL 검증 (데이터 품질 게이트)
[2단계] 적재 후 — SPARQL 쿼리 단위 테스트 (기능 검증)
[3단계] 적재 후 — 추론 규칙 검증 (Axiom 정합성)
[4단계] E2E   — 실제 질문 → 답변 정확도 검증
```

---

## 2. [1단계] SHACL 검증 — 적재 전 데이터 품질 게이트

### 2-1. 실행 방법

```python
from pyshacl import validate

data_graph = Graph()
data_graph.parse("fund_ontology.ttl", format="turtle")

shacl_graph = Graph()
shacl_graph.parse("fund_shacl.ttl", format="turtle")

conforms, results_graph, results_text = validate(
    data_graph,
    shacl_graph=shacl_graph,
    inference="rdfs",
    abort_on_first=False
)

print(f"검증 통과: {conforms}")
if not conforms:
    print(results_text)
```

### 2-2. 예상 위반 항목 및 허용 기준

| 위반 유형 | 예상 건수 | 허용 여부 | 조치 |
|----------|---------|---------|------|
| 운용회사 코드 누락 | ~66건 | 불허 | 적재 제외 |
| 위험등급 NULL | ~18,416건 | 허용 (OWA) | 트리플 미생성 |
| 수익률 NULL | 최대 44,782건 | 허용 | 트리플 미생성 |
| 순자산 음수 | 확인 필요 | 불허 | 로그 후 제외 |
| 환헤지 이상값 | 1건 | 불허 | NULL 처리 |

## 3. [2단계] SPARQL 단위 테스트

각 역량 질문(01_범위결정.md)에 대한 SPARQL 쿼리를 작성하고 결과가 비어있지 않은지 확인한다.

### TC-01. 판매중 주식형 펀드 조회

```sparql
SELECT (COUNT(?f) AS ?cnt) WHERE {
    ?f a :EquityFund ;
       :saleStatus "판매중" .
}
```

**기대값**: 약 36,000건 이하 (판매중 필터 후 감소)
**실패 조건**: 결과 0건

---

### TC-02. 위험등급 범위 탐색 (이행성 추론)

```sparql
# "보통 위험보다 위험한 등급의 판매중 펀드 수"
SELECT (COUNT(?f) AS ?cnt) WHERE {
    ?f :saleStatus "판매중" ;
       :hasRiskGrade ?g .
    ?g :riskierThan :riskgrade/3 .
}
```

**기대값**: 양수 (높은위험 + 다소높은위험 + 매우높은위험 합산)
**실패 조건**: 0건 → 이행성 추론이 작동하지 않음

---

### TC-03. 역관계 추론 (InverseOf)

```sparql
# 운용회사가 관리하는 펀드 목록
SELECT ?f WHERE {
    :company/80021 :manages ?f .
}
```

**기대값**: 한국밸류자산운용 운용 펀드 목록
**실패 조건**: 0건 → :managedBy owl:inverseOf :manages 추론 미작동

---

### TC-04. 같은 벤치마크 펀드 탐색

```sparql
SELECT ?similar ?name WHERE {
    :fund/KR5174430032 :followsBenchmark ?idx .
    ?similar :followsBenchmark ?idx ;
             :saleStatus "판매중" ;
             rdfs:label ?name .
    FILTER(?similar != :fund/KR5174430032)
}
```

**기대값**: KOSPI200 25% + KAP Bond Index 01Y 75%를 추종하는 다른 펀드
**실패 조건**: 0건

---

### TC-05. 해외 + 환헤지 복합 필터

```sparql
SELECT (COUNT(?f) AS ?cnt) WHERE {
    ?f :overseasFundType "해외" ;
       :isHedged true ;
       :saleStatus "판매중" .
}
```

**기대값**: 양수
**실패 조건**: 0건 → exchdg_yn 변환 오류 가능성

---

### TC-06. 운용회사 인스턴스 수 검증

```sparql
SELECT (COUNT(DISTINCT ?c) AS ?cnt) WHERE {
    ?c a :AssetManagementCompany .
}
```

**기대값**: 67
**실패 조건**: 67 미만 → 일부 운용사 인스턴스 미생성

---

### TC-07. 필수 속성 완전성 검증

```sparql
# fundId 없는 펀드가 있으면 안 됨
SELECT ?f WHERE {
    ?f a :PublicFund .
    FILTER NOT EXISTS { ?f :fundId ?id }
}
```

**기대값**: 0건 (없어야 함)
**실패 조건**: 1건 이상 → SHACL 통과 후에도 누락 발생

## 4. [3단계] Axiom 정합성 검증

### 4-1. Disjoint 클래스 위반 확인

```sparql
# 두 개 이상의 유형으로 분류된 펀드 (있으면 안 됨)
SELECT ?f (COUNT(?type) AS ?typeCount) WHERE {
    ?f a ?type .
    VALUES ?type { :EquityFund :BondFund :BondMixedFund :EquityMixedFund
                   :FoFund :MMF :MixedAssetFund :SpecialAssetFund }
}
GROUP BY ?f
HAVING (COUNT(?type) > 1)
```

**기대값**: 0건
**실패 조건**: 1건 이상 → 클래스 Disjoint 위반

---

### 4-2. 위험등급 순서 데이터 검증

```sparql
SELECT ?grade ?order WHERE {
    ?grade a :RiskGrade ;
           :gradeOrder ?order .
}
ORDER BY ?order
```

**기대값**: 1~6 순서로 6개 반환
**실패 조건**: 6개 미만 또는 순서 오류

---

### 4-3. 전체 트리플 수 범위 검증

```python
# 파이썬 검증 스크립트
g = Graph()
g.parse("fund_ontology.ttl", format="turtle")

total = len(g)
fund_count = len(list(g.subjects(RDF.type, BASE["PublicFund"])))

assert 90000 <= fund_count <= 96000, f"펀드 인스턴스 수 이상: {fund_count}"
assert total >= fund_count * 5, f"트리플 수 너무 적음: {total}"

print(f"펀드 인스턴스: {fund_count}개")
print(f"총 트리플: {total}개")
print(f"펀드당 평균 트리플: {total/fund_count:.1f}개")
```

## 5. [4단계] E2E 질문-답변 정확도 검증

실제 파이프라인(질문 → Intent분류 → SPARQL/NL2SQL → 답변)을 통해 검증.

| 테스트 질문 | 기대 답변 유형 | 확인 포인트 |
|-----------|-------------|-----------|
| "판매 중인 MMF 펀드를 알려줘" | MMF 목록 | :saleStatus 필터 작동 |
| "위험등급이 낮은 채권형 펀드는?" | 채권형 + 낮은위험 교집합 | 두 필터 AND 연결 |
| "삼성자산운용이 운용하는 주식형 펀드 수는?" | 숫자 | managedBy + 서브클래스 |
| "1년 수익률 상위 5개 펀드는?" | 순위 목록 | returnYear1 정렬 |
| "이 펀드의 실시간 기준가는?" | "답변할 수 없습니다" | 답변불가 차단 |
| "어떤 펀드를 사야 할까요?" | "투자 권유 불가" | 투자 권유 차단 |

## 6. 품질 지표 목표값

| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| 인스턴스 생성 비율 | ≥ 99.9% | (생성 건수 / 전체 행 수) × 100 |
| 필수 속성 완전성 | 100% | fundId, fundName, managedBy 누락 0건 |
| SHACL 위반 (불허 항목) | 0건 | 자동 검증 |
| 클래스 분류 오류 | 0건 | Disjoint 쿼리 결과 0건 |
| 역량 질문 TC 통과율 | 100% (7/7) | 단위 테스트 |
| E2E 답변불가 차단율 | 100% | 투자 권유·실시간 질문 |

## 7. 재생성 트리거 조건

온톨로지를 재생성해야 하는 경우:

| 트리거 | 재생성 범위 |
|--------|-----------|
| 원본 데이터 신규 버전 배포 | 전체 재생성 |
| 펀드 유형 매핑 오류 발견 | 전체 재생성 |
| 운용회사 신규 등록 | 운용회사 인스턴스만 추가 |
| 위험등급 기준 변경 | 위험등급 + 연결 트리플 재생성 |
| 벤치마크명 정규화 오류 | 벤치마크 인스턴스 + 연결 트리플 재생성 |

> 재생성 파이프라인은 멱등성(Idempotent)을 보장해야 한다.
> 같은 원본 데이터로 두 번 실행하면 동일한 TTL이 출력되어야 함.
